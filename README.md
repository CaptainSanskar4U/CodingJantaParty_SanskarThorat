# Orbitwin — Emergency Response Intelligence

Orbitwin is a local-first emergency-call review workspace built on the supplied
black-and-red Orbitwin dashboard. It ingests a consented recording, runs the
analysis locally, and turns the result into an investigator-reviewable case and
report.

The dashboard is a responsive, full-screen operations console. The visual system
uses matte black and graphite surfaces, one signal-red accent, Inter for UI text
and JetBrains Mono for timestamps and IDs. A native three-zone CSS grid replaces
the old fixed 1536×1024 stage and fractional transform scaling, so text and map
edges stay sharp at every desktop size. Existing element IDs and API hooks are
preserved. The Vecna landing page remains at `/`; `/console` opens the login
screen when there is no authenticated session.

## What is implemented

| Area | Implementation |
| --- | --- |
| Ingestion | Async upload with extension, MIME, size and duration validation; ffmpeg normalisation to mono 16 kHz WAV; SHA-256 of the original file; waveform peaks. |
| Live microphone | Optional near-real-time mode. The browser records mono 16 kHz WAV in 5-second chunks and sends each chunk to the authenticated server. A server-side Gemini adapter returns provisional text; the full recording is uploaded on Stop for the normal local final analysis. No key reaches the browser. |
| Speech | faster-whisper. `small` for Hindi/Hinglish transcription and Hindi→English translation; `base` for English. Language detection and probability are persisted. |
| Speaker attribution | MFCC feature clustering with automatic speaker-count selection. Labelled explicitly as heuristic clustering, not overlap-aware diarisation. |
| Vocal emotion | `superb/wav2vec2-base-superb-er` top-label prediction plus prosodic features (pitch, pause ratio, speech rate). Kept separate from transcript sentiment. |
| Transcript sentiment | Small, transparent bilingual term lists. No LLM and no hidden sentiment model. |
| Audio events | `MIT/ast-finetuned-audioset-10-10-0.4593` AudioSet predictions over 10-second windows, plus signal-based silence/low-audio detection. |
| Findings | Controlled phrase matching against an editable, labelled reference pack (`data/reference_pack.json`). Original transcript matches are preferred; translation matches are marked and down-weighted. |
| Triage | Transparent 0–100 urgency score with per-signal contribution breakdown. It is decision support, not a diagnosis or proof. |
| Map | Real Leaflet + OpenStreetMap tiles. Spoken landmarks are geocoded with Nominatim and cached in SQLite; a local Mumbai/Delhi gazetteer is the fallback. No fake pins. |
| Cases | Persistent cases, linked calls, notes, status/priority updates, finding review, search and audit events. |
| Alerts | Rule-driven alerts generated by completed analyses; acknowledge/dismiss status is persisted. |
| Reports | HTML report (print to PDF from the browser) and JSON evidence bundle. Reports include hashes, reference sources, review status and limitations. |
| Auth | bcrypt password hashing, server-side sessions, HttpOnly/SameSite cookies, CSRF tokens on every mutating API, API-wide auth middleware, and a failed-login throttle. |
| Interface | Full-screen responsive blackglass console with a compact sidebar, call queue, active-call/transcript workspace and Signals/Location/Audio rail. Real Leaflet/OSM maps use dark grayscale tiles with red markers. All panels and overlays use native CSS layout, not fractional scaling. |
| Demo | Two clearly labelled synthetic scenarios generated with edge-tts: Hinglish distress/digital-arrest and English help near Marine Drive. |

## What is deliberately not claimed

- **No live telephony.** Auto-answer is unavailable without a provider adapter and
  real credentials. Live microphone capture is not a telephone intercept. The
  supported workflow is upload, labelled demo, or consented room microphone
  capture. The `/api/telephony/incoming` endpoint returns an honest unavailable
  response.
- **No official agency codebook.** The reference pack is an editable sample. It
  must be replaced with an authorised codebook before operational use.
- **No detection of deception, guilt, coercion or kidnapping.** The vocal-emotion
  model predicts acoustic emotion labels only; it is not a lie detector. The UI
  and reports state this.
- **No validated Hindi vocal-emotion model.** The emotion model is English-trained.
  Hindi/Hinglish vocal predictions are shown with a limitations note.
- **No exact caller location.** Spoken landmarks are approximate. Investigator
  locations are labelled as investigator-entered, not device GPS.
- **Gemini text is provisional.** Live transcription can be wrong, can omit
  speech, and is not evidence by itself. The final local transcript, findings and
  map replace it after Stop. Audio is sent to Google only while live mode is
  active; do not use the feature without consent.

## Requirements

- Python 3.13 recommended (tested on 3.13.7)
- `ffmpeg` and `ffprobe` on `PATH` (tested with ffmpeg 9.0.1)
- 12 GB RAM recommended for CPU inference; no GPU is required
- Windows, macOS or Linux
- Optional live mode: a Google Gemini API key stored only in the server-side
  `.env`, plus network access and available quota. Without it, the app records
  locally and runs the normal final analysis after Stop.

Install:

```powershell
python -m pip install -r requirements.txt
```

The first analysis downloads the Whisper, AST and emotion models into the
Hugging Face cache. The demo was tested with:

- transformers 5.17.0
- faster-whisper 1.2.1
- edge-tts 7.3.1
- FastAPI 0.115.6

### Optional live transcription key

Create a **fresh** Gemini key in Google AI Studio. Do not reuse a key that has
appeared in chat, a screenshot, a commit or browser storage. Put it only in the
server-side `.env`:

```dotenv
GEMINI_API_KEY=replace-with-a-fresh-key
GEMINI_MODEL=gemini-2.5-flash
```

Then restart uvicorn. The key is never returned by `/api/config/status` or
`/api/live/config`, and the browser calls only the same-origin `/api/live/transcribe`
route. A missing key is not fatal: the live window still records and the final
analysis runs locally. The pasted key from earlier development is treated as
exposed and must not be used; revoke it in AI Studio and use a replacement.

## Demo path

1. Sign in.
2. Click **Add Recording**.
3. Choose **Hinglish · distress + digital-arrest scam indicators** and click
   **Load & analyse**. On CPU this can take roughly 1–3 minutes.
4. Review the transcript, translation, speaker chips, vocal-emotion note,
   audio events, Dadar map, findings and urgency breakdown.
5. Click **Save to Case** (or open the prepared case from **Investigations**).
6. Review findings, add an investigator note, and download the HTML or JSON
   report.

The second demo, **English · help request near Marine Drive**, exercises the
English path without translation.

### Optional live microphone demo

1. Put a fresh server-side `GEMINI_API_KEY` in `.env` and restart uvicorn.
2. Click **Go Live** (or **Add Recording → Go Live**).
3. Confirm consent. The window states that audio leaves the device for Google
   Gemini while live mode is active.
4. Choose a language hint (Auto, Hinglish, Hindi or English) and optionally link
   the recording to a case.
5. Click **Start listening**. The browser records the microphone in mono 16 kHz
   WAV segments; each 5-second segment calls the authenticated
   `/api/live/transcribe` route. The transcript shown there is provisional.
6. Click **Stop & analyse**. The full recording is uploaded through the normal
   recording endpoint, then the local pipeline produces the final transcript,
   findings, urgency and map. The provisional Gemini text is not persisted as
   the evidence transcript.
7. If the key, network, microphone or quota fails, the UI says so and keeps
   recording locally; **Stop & analyse** still works. **Cancel** discards the
   session without uploading.

Live mode is capped at the normal 5-minute recording limit. Keep the default
12 requests/minute unless your Gemini quota supports more. For a reliable stage
demo, prewarm the map cache and test the exact microphone and network first:

```powershell
python scripts/prewarm_map.py --check-tiles
```

Regenerate the synthetic demo audio (requires ffmpeg and network access for
edge-tts):

```powershell
python scripts/make_demo_audio.py
```

The script writes `data/demo/scenarios.json` and the two WAV files. Demo audio
and its metadata are explicitly marked synthetic.

## Security notes

- API routes require an authenticated session when `ORBITWIN_AUTH=1`.
- Mutating routes require the per-session CSRF header.
- Session cookies are HttpOnly and SameSite=Lax. `secure=False` is appropriate
  only for local HTTP; set it to `True` when serving over HTTPS.
- Upload files are renamed with generated IDs, extension-whitelisted, probed
  with ffprobe, size/duration-limited and hashed with SHA-256.
- Reports HTML-escape persisted content.
- SQL uses parameters, not string interpolation.
- The Gemini key is read only by the server process; it is never included in
  static files, API responses or browser code. Provider errors are redacted.
- Live chunks are authenticated, CSRF-protected, content/size/duration-checked,
  rate-limited per user and session-capped. Temporary chunks are deleted after
  each request. Live transcript text is provisional and is not persisted as the
  evidence transcript.
- A strict-ish Content-Security-Policy, `nosniff`, `DENY` framing and
  `no-referrer` headers are set.
- The SQLite database and audio files are **not encrypted at rest**. Protect
  the machine and data directory, or add OS/volume encryption for production.
- This is a single-investigator local app; there is no multi-tenant role model,
  MFA, remote audit sink or secure deletion guarantee.

## Known blockers and limitations

- No telephony provider credentials or adapter: live calls cannot be answered.
  The live microphone is a browser capture, not a phone intercept.
- No authorised distress/scam codebook: the reference pack is a labelled sample.
- Vocal emotion is not validated for Hindi/Hinglish and is not deception
  detection.
- Speaker clustering is heuristic and does not model overlapping speech.
- CPU inference is slow. Measured Hinglish demo: about 130 seconds for 30
  seconds of audio; the UI shows progress and keeps the queue usable.
- Live Gemini mode needs a valid server-side key, network access and quota. The
  exposed key from earlier development is not valid for a secure demo. A Gemini
  rate limit or outage degrades to local recording; it does not fabricate text.
- Nominatim is a public service. The app caches results and falls back to a
  local gazetteer, but a production deployment should use a self-hosted
  geocoder or a provider with an appropriate usage agreement.
- OSM tile usage is subject to the OpenStreetMap tile usage policy. A production
  deployment should use an appropriate tile provider. The UI shows a network
  warning if tiles fail but still displays real coordinates and markers.
